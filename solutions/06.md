# Défi 06 : Réservation de salle

**Difficulté :** ★★☆ · **Famille :** le clic arrive, le code déraille.

## Cause

Le bouton est dans un `<form>` et n'a pas d'attribut `type` :

```html
<form id="booking-form" class="booking">
  ...
  <button class="btn btn-primary" id="confirm-booking">Valider la commande</button>
</form>
```

Le `type` par défaut d'un `<button>` dans un formulaire est **`submit`**. Le clic déclenche
donc deux choses : le handler `confirmBooking`, **et** la soumission du formulaire.
Le formulaire n'a ni `action` ni `method` : le navigateur navigue vers la même URL en `GET`
avec les champs en query string. Cette navigation détruit le contexte JavaScript de la page.

Et le handler ne résiste pas à la course :

```js
function confirmBooking() {
  var f = readForm();
  logLine('réservation demandée : ' + f.slot);
  collectClientContext().then(function (ctx) {   // setTimeout de 120 ms
    return fetch('/api/challenge/06/solve', { ... });
  })
  ...
}
```

Il attend une collecte asynchrone de 120 ms avant d'appeler `fetch`. La navigation part
immédiatement : la promesse n'est jamais résolue, **le fetch n'est même pas créé**.
Aucun `preventDefault()` nulle part.

## Diagnostic pas à pas

1. Clique. La page **clignote** et l'URL devient
   `/challenge/06?date=...&slot=09%3A00-10%3A00&seats=6&costCenter=RD-4120&...`.
   Une URL qui gagne une query string après un clic = **soumission de formulaire**.
   Le journal de la carte se vide aussi : la page a été rechargée.
2. **Network** → coche **Preserve log** avant de cliquer. Tu vois alors la navigation
   `challenge/06?...` de type `document` en tête de liste, et **aucune** requête
   `challenge/06/solve`.
3. **Elements** : le bouton est dans `<form id="booking-form">` et n'a pas de `type`.
   ```js
   document.getElementById('confirm-booking').type   // "submit"
   document.getElementById('confirm-booking').form   // <form id="booking-form">
   ```
4. **Sources** : le handler appelle `collectClientContext()` (un `setTimeout` de 120 ms) avant
   `fetch`. Même sans ce délai la course serait perdue ; avec, elle l'est à coup sûr.
5. Pour le voir en direct : Sources → **Event Listener Breakpoints** → *Control* → `submit`.
   Le débogueur s'arrête sur la soumission au moment du clic.

## Contournements

**A. Changer le type du bouton (Elements)**
Ajoute `type="button"` sur `<button id="confirm-booking">`. Il ne soumet plus rien, seul le
handler `click` s'exécute.

**B. Bloquer la soumission (Console)**
```js
document.getElementById('booking-form')
  .addEventListener('submit', e => e.preventDefault());
document.getElementById('confirm-booking').click();
```
(ou `document.getElementById('booking-form').onsubmit = () => false;`)

**C. Rejouer la requête**
```js
await fetch('/api/challenge/06/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '06', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

**Preserve log** est le premier réflexe dès qu'une page « clignote » : sans lui, le Network se
vide à chaque navigation et tu ne vois jamais ce qui est parti (ou pas).
Dans un `<form>`, un `<button>` sans `type` est un `submit`. Un handler asynchrone (`await`,
`.then`, `setTimeout`) qui précède l'envoi perd toujours la course contre la navigation.
Corollaire : `e.preventDefault()` doit être **la première ligne** du handler, pas la dernière.
