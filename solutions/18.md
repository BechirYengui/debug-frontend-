# Défi 18 : Réarmement d'une alarme

**Difficulté :** ★★★ · **Famille :** le clic arrive, le code déraille.
Le code est dans `public/c/18.js`, minifié sur une ligne.

## Cause

L'écouteur du bouton est posé avec l'option `once` :

```js
function h(e) {
  if (!e.isTrusted) { log("auto-test du bouton OK"); return; }
  tx();
}
E.go.addEventListener("click", h, { once: true, passive: true });   // <- once
```

et l'initialisation se termine par un « auto-test » qui **déclenche un clic synthétique** sur
ce même bouton :

```js
function selftest() {
  E.go.dispatchEvent(new MouseEvent("click", { bubbles: true, cancelable: true }));
}
...
opts(); upd(); selftest(); log("alarme TEMP-HIGH chargée, 3 capteurs");
```

Un événement créé par `dispatchEvent` a `isTrusted === false` : `h()` journalise
« auto-test du bouton OK » et s'arrête sans appeler `tx()`. Mais pour le navigateur,
**l'écouteur a été invoqué**, et `once: true` le **retire aussitôt**. Quand l'humain clique,
le bouton n'a plus aucun écouteur `click`. Rien ne se passe : pas de log, pas de requête,
pas d'erreur. `tx()`, qui contient un `fetch` parfaitement correct, n'est jamais appelée.

## Diagnostic pas à pas

1. **Network** au clic : rien. **Console** : rien. Le bouton ne réagit pas du tout : pas même
   une ligne dans le journal de la page. Regarde ce journal : au chargement, il contient
   « auto-test du bouton OK ». Quelque chose a donc déjà « cliqué » pour toi.
2. **Elements** → sélectionne le bouton `#rearm-alarm` → onglet **Event Listeners**
   (décoche *Ancestors* pour n'avoir que l'élément) : **aucun `click`**. Dans la Console,
   `getEventListeners($0)` renvoie `{}`. Le code pose pourtant un écouteur : il a été retiré.
3. **Sources** → `18.js` → **`{}`** Pretty print → `Ctrl+F` `addEventListener("click"`.
   Tu trouves `E.go.addEventListener("click", h, {once: true, passive: true})`, puis juste
   en dessous `selftest()`, dont le corps fait un `dispatchEvent(new MouseEvent("click", …))`.
4. Preuve par le débogueur : pose un point d'arrêt sur la ligne `selftest();` et **recharge**.
   À la pause, retourne dans Elements → Event Listeners du bouton : l'écouteur `click` est
   là, avec **`once` coché**. Reprends (`F8`) : il disparaît. Le coupable est l'instruction
   que tu viens de franchir.
5. Autre angle : Sources → **Event Listener Breakpoints** → *Mouse* → coche **click**, puis
   recharge. Le débogueur s'arrête dans `h()` **pendant le chargement**, avant tout clic
   humain ; dans le panneau Scope, `e.isTrusted` vaut `false`. Un `click` synthétique compte
   comme une invocation pour `once`.

## Contournements

**A. Neutraliser l'auto-test avant qu'il ne consomme l'écouteur**
Point d'arrêt sur la ligne `selftest();` (fichier pretty-printé), recharge. À la pause, dans
la Console (contexte de la closure) :
```js
E.go.dispatchEvent = function () {}
```
Puis `F8`. `selftest()` appelle désormais une fonction vide, l'écouteur `once` survit, et ton
vrai clic appelle `tx()` → **200**.

**B. Reposer l'écouteur depuis n'importe quelle pause dans la closure**
Il suffit d'être en pause dans le scope du script pour atteindre `E` et `tx`. Par exemple :
point d'arrêt dans `upd()` (première ligne), puis change la valeur du select « Intervention »
pour le déclencher. À la pause, dans la Console :
```js
E.go.addEventListener('click', tx)
```
`F8`, puis clique sur « Valider la commande » : `tx()` part, sans `once` cette fois.
(Variante : `E.go.addEventListener('click', h)` remet l'écouteur d'origine, qui teste
`isTrusted` : un vrai clic passe.)

**C. Rejouer la requête depuis la Console**
```js
await fetch('/api/challenge/18/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '18', action: 'validate' })
}).then(r => r.json());
```

**D. Vérifier son diagnostic avec `getEventListeners`**
Ce n'est pas un contournement, mais c'est l'outil qui tranche en une ligne : sélectionne le
bouton dans Elements, puis dans la Console `getEventListeners($0)` → `{}` avant réparation ;
après A ou B → `{click: [{listener: ƒ, once: false, passive: false, …}]}`. Sur la pause du
contournement A, avant `F8`, tu verrais `once: true`.

## Le réflexe à garder

**Event Listeners vide alors que le code pose un écouteur = il a été retiré.** Les deux
suspects habituels : l'option **`once`** (retiré après la première invocation) et l'option
**`signal`** (retiré quand un `AbortController` est annulé). Et retiens que
**`dispatchEvent` compte comme une invocation** : un auto-test, un `.click()` d'initialisation
ou un framework qui « simule » un événement suffisent à consommer un `once`. Le champ
`isTrusted` distingue le clic humain du clic synthétique, mais il ne protège pas l'écouteur.
