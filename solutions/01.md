# Défi 01 : Promotion de release

**Difficulté :** ★☆☆ · **Famille :** le clic n'arrive jamais au bouton.

## Cause

`challenges/01.html` monte un `<div id="view-transition">` juste avant la carte.
`public/c/01.css` lui donne :

```css
.view-transition{ position: fixed; inset: 0; z-index: 9000; background:#0b0e14; opacity: 1; }
.view-transition.is-idle{ opacity: 0; }
```

Le script ajoute `is-idle` au premier `requestAnimationFrame` : le voile devient **invisible**
(`opacity: 0`) mais reste dans le flux, en `position: fixed`, sur toute la fenêtre et au-dessus
de la carte. `opacity: 0` n'a aucun effet sur le hit-testing : le voile continue de recevoir
tous les clics. Le handler du bouton (`el.promote.addEventListener('click', send)`) est
correctement posé, il n'est simplement jamais appelé.

C'est le bug de production classique : un écran de transition dont on anime l'opacité au lieu
de le démonter (`display:none`, `remove()`, `pointer-events:none`).

## Diagnostic pas à pas

1. **Console** : rien. Aucune erreur. Premier signal : le problème n'est pas dans le JS.
2. **Network** : aucune requête au clic. Le fetch n'est jamais atteint.
3. **Elements** → clic droit sur le bouton dans la page → *Inspecter*.
   DevTools sélectionne `div#view-transition`, **pas** le `<button>`. C'est la réponse.
   (DevTools inspecte l'élément réellement sous le curseur, celui qui recevrait le clic.)
4. Confirme en Console :
   ```js
   document.elementFromPoint(
     ...(r => [r.left + r.width/2, r.top + r.height/2])(document.querySelector('#promote').getBoundingClientRect())
   )
   // <div id="view-transition" class="view-transition is-idle">
   ```
5. Sélectionne `#view-transition` dans Elements : le rectangle surligné couvre toute la fenêtre.
   Onglet **Styles** → `position: fixed; inset: 0; z-index: 9000`.

## Contournements

**A. Supprimer le nœud (Elements)**
Sélectionne `div#view-transition` → touche `Suppr`. Le clic passe, la requête part.

**B. Neutraliser en CSS (Styles)**
Sur `.view-transition`, ajoute `pointer-events: none;` (ou `display: none`).
La règle live-éditée suffit, pas besoin de toucher au fichier.

**C. Depuis la Console**
```js
document.getElementById('view-transition').remove();
document.getElementById('promote').click();
```

**D. Rejouer la requête sans toucher au DOM**
```js
await fetch('/api/challenge/01/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '01', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

Un bouton qui ne réagit pas et une Console vide : **avant de lire le JS, vérifie qui reçoit
vraiment le clic**. `Inspecter` sur l'élément, ou `document.elementFromPoint(x, y)`.
`opacity: 0` et `visibility: hidden` ne désactivent pas les événements ; `display: none` et
`pointer-events: none` si.
