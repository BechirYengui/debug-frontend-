# Défi 08 : Clôture d'un ticket

**Difficulté :** ★★★ · **Famille :** le clic arrive, le code déraille.
Le code est dans `public/c/08.js`, minifié sur une ligne.

## Cause

Le handler du bouton :

```js
E.close.addEventListener("click", function () {
  busy(true);
  try {
    var p = payload();
    tx(p);
  } catch (err) {}      // <- bloc vide
  busy(false);
});
```

et le constructeur de payload :

```js
function payload() {
  return {
    challengeId: "08",
    action: "validate",
    ticket: T.id,
    resolution: st.res,
    closedBy: ss.profile.handle,   // <- ss.profile est undefined
    notify: st.notify
  };
}
```

`ss.profile` n'est affecté que sous condition, plus haut :

```js
var ss = { id: "sess-7712", roles: ["agent", "reader"], since: Date.now() };
if (ss.roles.indexOf("supervisor") !== -1) { ss.profile = { handle: "n2-lead", scope: "all" }; }
```

La session courante a les rôles `agent` et `reader`, jamais `supervisor` : `ss.profile` reste
`undefined`. `payload()` lève `TypeError: Cannot read properties of undefined (reading 'handle')`.
Le `catch (err) {}` vide l'absorbe : pas de log, pas de trace, la Console reste immaculée.
`tx(p)` : qui contient un `fetch` parfaitement correct : n'est jamais atteint.

Le bouton, lui, **répond visiblement** : `busy(true)` puis `busy(false)` font clignoter le
libellé en « envoi... ». On croit qu'il se passe quelque chose. C'est le piège.

## Diagnostic pas à pas

1. **Network** : rien au clic. **Console** : rien non plus. Mais le bouton réagit
   visuellement → le handler s'exécute bel et bien, il s'interrompt en cours de route.
2. **Sources** → panneau de droite → coche **Pause on uncaught exceptions**, puis la
   sous-case **Pause on caught exceptions**. C'est le geste décisif de ce défi : par défaut,
   DevTools ignore les exceptions rattrapées, donc celles qu'un `catch` vide fait disparaître.
3. Clique. Le débogueur s'arrête sur `closedBy: ss.profile.handle`, avec l'infobulle
   `TypeError: Cannot read properties of undefined (reading 'handle')`.
   Survole `ss` : `{id: "sess-7712", roles: ["agent","reader"], since: ...}` : pas de `profile`.
4. Remonte la **Call Stack** : `payload` ← le handler `click`. Regarde le code autour :
   `try { ... } catch (err) {}`. Le bloc est vide, l'erreur est perdue.
5. Approche alternative, sans les cases à cocher : Sources → **Event Listener Breakpoints** →
   *Mouse* → `click`, clique, puis `F10` / `F11` pas à pas. Tu vois l'exécution entrer dans
   `payload()` et ressortir directement à `busy(false)` en sautant `tx(p)`.
6. Le code est sur une ligne : clique sur **`{}`** (Pretty print) en bas du panneau Sources
   avant de poser tes points d'arrêt, sinon tout le fichier est une seule ligne 1.

## Contournements

**A. Réparer la donnée manquante, puis cliquer (Console)**
`ss` est dans une closure, mais le point d'arrêt te donne accès à son scope. Mets un point
d'arrêt dans `payload()`, clique, et dans la Console (dans le contexte de la pause) :
```js
ss.profile = { handle: 'n2-lead' };
```
Reprends l'exécution (`F8`), puis reclique sur le bouton : `payload()` ne lève plus, `tx()`
part, le serveur répond 200.

**B. Point d'arrêt conditionnel / logpoint**
Clic droit sur la ligne `closedBy: ...` → *Add conditional breakpoint* → condition :
```js
(ss.profile = ss.profile || {handle: 'n2-lead'}) && false
```
La condition affecte la valeur puis renvoie `false` : le débogueur ne s'arrête jamais et le
bug est corrigé à la volée. (Même principe avec un *Logpoint*.)

**C. Rejouer la requête**
```js
await fetch('/api/challenge/08/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '08', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

Un handler qui **réagit visuellement** mais n'envoie rien = il s'arrête au milieu.
**Pause on caught exceptions** est la case qui révèle tout ce qu'un `catch {}` vide cache ;
la plupart des devs ne la cochent jamais. Et sur du code minifié, **Pretty print (`{}`) avant
tout** : sans lui, breakpoints et pas-à-pas sont inutilisables.
