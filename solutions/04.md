# Défi 04 : Publication d'un article

**Difficulté :** ★★☆ · **Famille :** le clic n'arrive jamais au bouton.

## Cause

La carte « Contrôle avant mise en ligne » (`#metrics`, classe `.editor-metrics`) porte un
pseudo-élément décoratif qui **déborde vers le bas** :

```css
.editor-metrics{ position: relative; z-index: 3; }
.editor-metrics::after{
  content: "";
  position: absolute;
  left: -14px; right: -14px;
  top: 100%;          /* commence sous la carte */
  height: 250px;      /* et descend sur 250 px */
  background: linear-gradient(180deg, rgba(94,234,212,.07), rgba(94,234,212,0) 78%);
}
```

`top: 100%` place le dégradé **après** la carte, et 250 px de hauteur le font recouvrir toute
la carte d'action qui suit : dont le bouton. Comme `.editor-metrics` est positionné avec
`z-index: 3` et que `.editor-actions` reste statique, le pseudo-élément est peint **au-dessus**
du bouton. Le hit-testing suit l'ordre de peinture : c'est le `::after` qui capte le clic.

Le dégradé est presque transparent (7 % d'opacité en haut) : à l'œil, on ne voit rien.

## Diagnostic pas à pas

1. Console vide, Network vide au clic → ce n'est pas le JS.
2. **Elements** → clic droit sur le bouton → *Inspecter*. DevTools sélectionne
   `div#metrics.card.editor-metrics`, pas le bouton. Un voisin reçoit le clic.
3. Déplie `#metrics` dans l'arbre : DevTools affiche un nœud `::after` en enfant. Survole-le :
   la zone surlignée dans la page **descend bien au-dessus de la barre d'action**.
4. Sélectionne `::after` → onglet **Styles** : `position:absolute; top:100%; height:250px`.
5. Confirme :
   ```js
   const b = document.getElementById('publish').getBoundingClientRect();
   document.elementFromPoint(b.left + b.width/2, b.top + b.height/2);
   // <div id="metrics" class="card editor-metrics">   (le ::after n'est pas un noeud DOM :
   //  elementFromPoint renvoie son element hote)
   ```
   Ce décalage : « je vise le bouton, on me renvoie une carte située au-dessus » : est la
   signature d'un pseudo-élément ou d'un enfant absolu qui déborde.

## Contournements

**A. Rendre l'hôte transparent au pointeur (Styles)**
Sur `.editor-metrics`, ajoute `pointer-events: none;`. Le pseudo-élément hérite et laisse
passer le clic. (La carte metrics n'a aucun contrôle interactif, aucun effet de bord.)

**B. Neutraliser le pseudo-élément (Styles)**
Sélectionne le nœud `::after` dans Elements et mets `content: none;`, `height: 0;` ou
`display: none;`.

**C. Sortir le bouton de la zone couverte (Elements)**
Glisse le nœud `<button id="publish">` plus haut dans l'arbre (par exemple juste avant
`#metrics`), ou fais-le remonter en Console :
```js
document.body.appendChild(document.getElementById('publish'));
document.getElementById('publish').click();
```

**D. Rejouer la requête**
```js
await fetch('/api/challenge/04/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '04', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

Les pseudo-éléments `::before` / `::after` sont peints, donc **cliquables**, et n'apparaissent
pas dans le HTML source : seulement dans l'arbre Elements de DevTools. Dès qu'un décor
(dégradé, ombre, séparateur, bandeau) est proche d'un contrôle mort, déplie les nœuds générés
et survole-les pour voir la zone qu'ils occupent réellement.
