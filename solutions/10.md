# Défi 10 : Virement interne

**Difficulté :** ★★★ · **Famille :** la requête part, mais elle est invalide.
Le code est dans `public/c/10.js`, minifié sur une ligne.

## Cause

Les en-têtes de l'application sont construits une fois pour toutes, au démarrage :

```js
E.hdr = {
  "Accept": "application/json",
  "X-Client": "backoffice-web/4.2",
  "X-Request-Id": "rq-" + Math.random().toString(36).slice(2, 10)
};
```

et réutilisés tels quels pour l'envoi :

```js
fetch("/api/challenge/10/solve", {
  method: "POST",
  headers: E.hdr,                 // <- pas de Content-Type
  body: JSON.stringify(p)         // <- le corps, lui, est du JSON valide
})
```

Il manque `Content-Type`. Quand `body` est une chaîne et qu'aucun `Content-Type` n'est fourni,
`fetch` n'échoue pas : il en **invente un**. La spécification impose alors
`text/plain;charset=UTF-8`. Le serveur reçoit donc du JSON parfaitement formé, annoncé comme
du texte brut, et le refuse avec un `415`.

C'est le bug le plus perfide de la série : le corps est juste, la méthode est juste, l'URL est
juste. Seule l'étiquette est fausse, et **personne dans le code n'a écrit `text/plain`**.

## Diagnostic pas à pas

1. **Network** : la requête part, `POST`, statut **415**. Méthode correcte : le problème est
   ailleurs que dans le verbe.
2. Onglet **Payload** : le corps est `{"challengeId":"10","action":"validate",...}`.
   Il est valide. Donc ce n'est pas le corps non plus.
3. Onglet **Headers** → section **Request Headers** :
   ```
   Content-Type: text/plain;charset=UTF-8
   X-Client: backoffice-web/4.2
   X-Request-Id: rq-...
   ```
   Cherche `text/plain` dans le code source : **introuvable**. C'est le signe que le
   navigateur l'a ajouté lui-même, faute d'en-tête explicite.
   (Si Chrome affiche « Provisional headers are shown », clique sur *Raw* pour voir les
   en-têtes réellement émis.)
4. Onglet **Response** : `Content-Type reçu : « text/plain;charset=UTF-8 ». Ce n'est pas le
   type de média que cet endpoint accepte.`
5. Le terminal `npm start` affiche la même chose, avec le corps brut à côté : la comparaison
   « ce que je crois envoyer / ce qui arrive » est immédiate.
6. **Sources** → `10.js` → **Pretty print `{}`** → cherche `headers`. L'objet `E.hdr` ne
   contient que trois clés, aucune n'est `Content-Type`.
   Vérification à chaud, sur un point d'arrêt posé sur la ligne du `fetch` :
   `Object.keys(E.hdr)` → `["Accept","X-Client","X-Request-Id"]`.

## Contournements

**A. Rejouer avec le bon en-tête (Console)**
```js
await fetch('/api/challenge/10/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '10', action: 'validate' })
}).then(r => r.json());
```

**B. Copy as fetch + une ligne**
Network → clic droit sur la requête → *Copy as fetch*. Colle en Console et ajoute
`"Content-Type": "application/json"` dans `headers`. Rien d'autre à changer : le body copié
est déjà bon. C'est la démonstration la plus parlante que le seul défaut est l'étiquette.

**C. Corriger l'objet d'en-têtes à chaud (point d'arrêt)**
Pose un point d'arrêt sur la ligne du `fetch` (après pretty-print), clique sur le bouton,
puis dans la Console pendant la pause :
```js
E.hdr['Content-Type'] = 'application/json';
```
Reprends (`F8`). L'en-tête étant partagé, tous les envois suivants sont corrects aussi.

**D. Intercepter `fetch`**
```js
const orig = window.fetch;
window.fetch = (u, i = {}) => orig(u, i.body
  ? { ...i, headers: { ...(i.headers || {}), 'Content-Type': 'application/json' } } : i);
document.getElementById('execute-transfer').click();
```

## Le réflexe à garder

Un `415` ne dit jamais « ton JSON est faux » : il dit « ton étiquette est fausse ».
Quand un en-tête apparaît dans Network **sans exister dans le code**, c'est le navigateur qui
l'a mis : `Content-Type`, `Content-Length`, `Origin`, `Referer`, `Sec-Fetch-*`.
Retiens la règle : `fetch` + `body` chaîne + pas de `Content-Type` = `text/plain;charset=UTF-8`.
(Avec un `FormData` ou un `URLSearchParams`, ce serait `multipart/form-data` ou
`application/x-www-form-urlencoded` : jamais du JSON.)
