# Défi 12 : Ouverture du coffre-fort

**Difficulté :** ★★★ · **Famille :** la requête part, mais elle est invalide.
Le code est dans `public/c/12.js`, minifié sur une ligne.

## Cause

Au chargement, la page négocie une session et **reçoit un jeton** :

```js
function ses() {
  return fetch("/api/session", { headers: { "Accept": "application/json" } })
    .then(function (r) { return r.json(); })
    .then(function (d) {
      K.t = d.token;              // <- le jeton est stocke ici
      K.ttl = d.expiresIn;
      K.scopes = d.scopes || [];
      E.sess.textContent = "ops-console / jeton " + mask(K.t);   // <- affiche masque
      ...
    });
}
```

`mask()` n'affiche que les 4 premiers et les 4 derniers caractères : la carte « Session »
montre `ops_....36de`. Le jeton complet vit dans `K.t`, dans une closure.

L'envoi, lui, ne le réutilise jamais :

```js
fetch("/api/challenge/12/solve", {
  method: "POST",
  headers: { "Content-Type": "application/json", "Accept": "application/json" },
  body: JSON.stringify({ challengeId: "12", action: "validate", path: S.path, ... })
})
```

Verbe correct, `Content-Type` correct, corps correct. Il manque l'en-tête
`X-Api-Token` que l'endpoint exige. Le serveur répond **401 :
« En-tête "X-Api-Token" absent de la requête reçue. »**

Contrairement aux 11 autres défis, **l'encart Objectif ne mentionne pas cette exigence** :
c'est la réponse du serveur qui te l'apprend. C'est le cas réel : un endpoint protégé dont la
doc est incomplete.

## Diagnostic pas à pas

1. **Network** : la requête part, `POST`, `Content-Type: application/json`, corps valide.
   Statut **401**.
2. Onglet **Response** : `En-tete « X-Api-Token » absent de la requete recue.`
   Le serveur a nommé l'en-tête manquant. Reste à trouver la valeur.
3. **Ne filtre pas le Network sur `solve`.** Remonte la liste complète des requêtes de la
   page : il y a un `GET /api/session` émis au chargement, bien avant ton clic.
   Ouvre-le → onglet **Response** :
   ```json
   { "ok": true, "session": "ops-console", "issuedAt": "...", "expiresIn": 3600,
     "scopes": ["vault:read","vault:unlock","challenge:solve"],
     "token": "ops_xxxxxxxxxxxxxxxxxxxxxxxx" }
   ```
   Le jeton complet est là. (Le bouton « renouveler » de la carte Session rejoue cet appel
   si tu as raté la première requête.)
4. Recoupement dans l'UI : la carte Session affiche `ops_....36de` : les 4 derniers caractères
   correspondent bien à ceux de la réponse. Tu tiens la bonne valeur.
5. Autre chemin, par le débogueur : **Sources** → `12.js` → **Pretty print `{}`** → point
   d'arrêt dans `ses()` sur la ligne `K.t = d.token`. Recharge, la pause survient, survole `d` :
   le jeton est dans l'objet. Ou, sur un point d'arrêt posé dans `tx()`, évalue simplement `K.t`.
6. Dernier chemin, le plus direct : dans la Console,
   `await (await fetch('/api/session')).json()` : l'endpoint est ouvert.

## Contournements

**A. Rejouer avec l'en-tête (Console) : récupère le jeton dynamiquement**
```js
const { token } = await (await fetch('/api/session')).json();
await fetch('/api/challenge/12/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-Api-Token': token },
  body: JSON.stringify({ challengeId: '12', action: 'validate' })
}).then(r => r.json());
```

**B. Copy as fetch + un en-tête**
Network → clic droit sur la requête `solve` → *Copy as fetch*. Colle en Console, ajoute
`'X-Api-Token': '<colle ici le token lu dans la reponse de /api/session>'` dans `headers`,
exécute. Une seule ligne change, tout le reste du payload d'origine est conservé.

**C. Injecter l'en-tête dans toutes les requêtes de la page**
```js
const orig = window.fetch;
const { token } = await (await fetch('/api/session')).json();
window.fetch = (u, i = {}) => orig(u, String(u).includes('/solve')
  ? { ...i, headers: { ...(i.headers || {}), 'X-Api-Token': token } } : i);
document.getElementById('unlock-vault').click();
```
C'est la version la plus proche du correctif réel : le bouton de la page fonctionne ensuite
normalement, avec son vrai payload.

## Le réflexe à garder

Un `401` / `403` sur une requête par ailleurs impeccable = **il manque un secret, pas une
correction de format**. Et ce secret est presque toujours déjà quelque part dans la page :
- une réponse reçue plus tôt dans l'onglet Network (`/session`, `/me`, `/config`, `/bootstrap`),
- un `data-*` dans le DOM,
- une variable JS accessible sur un point d'arrêt,
- le `localStorage` / `sessionStorage` (onglet **Application**),
- un cookie.

D'où le réflexe : **regarde toutes les requêtes de la page, pas seulement celle qui échoue.**
Le contexte d'authentification est presque toujours posé au chargement.
