# Défi 05 : Envoi d'un lot de notifications

**Difficulté :** ★★☆ · **Famille :** le clic arrive, le code déraille.

## Cause

Deux scripts, deux moments d'exécution :

```html
<head>
  ...
  <script src="/c/05-bindings.js"></script>   <!-- ni defer ni async : exécuté pendant le parsing du head -->
</head>
<body>
  ... le bouton #dispatch-batch est ici ...
  <script src="/c/05.js" defer></script>
</body>
```

`05-bindings.js` contient le handler complet (`onDispatch`, avec un `fetch` parfaitement
correct) et l'abonne via un helper maison :

```js
function on(selector, type, handler, opts) {
  var node = d.querySelector(selector);
  if (!node) return false;          // <-- échec silencieux
  node.addEventListener(type, handler, opts || false);
  bound += 1;
  return true;
}
on('#dispatch-batch', 'click', onDispatch);
```

Au moment où ce script s'exécute, le `<body>` n'est pas encore parsé :
`document.querySelector('#dispatch-batch')` renvoie `null`, le helper sort par `return false`
et **rien n'est abonné**. Aucune exception, aucun log : le helper avale l'échec.
Les abonnements du même fichier sur `window` et `document` (`beforeunload`, `visibilitychange`)
fonctionnent, eux, puisque ces objets existent déjà : la page a donc l'air « vivante ».

`05.js` (chargé en `defer`, donc après le parsing du DOM) gère le tableau, les filtres et
l'aperçu : tout ce qui marche vient de là.

## Diagnostic pas à pas

1. Console vide, Network vide au clic. Le bouton n'est ni recouvert ni `disabled` :
   `Inspecter` renvoie bien `button#dispatch-batch`.
2. **Elements** → bouton sélectionné → panneau **Event Listeners**, décoche *Ancestors*.
   La liste est **vide**. Il n'y a aucun handler : inutile de chercher pourquoi le fetch
   échoue, il n'est jamais atteint.
   En Console (Chrome) : `getEventListeners(document.getElementById('dispatch-batch'))` → `{}`.
3. **Sources** : ouvre `05-bindings.js`. On y trouve `onDispatch` avec le bon `fetch`, et
   `on('#dispatch-batch', 'click', onDispatch)`.
4. Pose un point d'arrêt sur la ligne `var node = d.querySelector(selector);` et recharge.
   La pause a lieu **avant** que le bouton n'existe : `node` vaut `null`, `document.body`
   vaut `null`, `document.readyState` vaut `"loading"`.
5. Regarde où le fichier est chargé : `<head>`, sans `defer` ni `async`. Compare avec `05.js`,
   chargé en fin de `<body>` avec `defer` : celui-là trouve tout.
6. La page expose même le compteur : en Console, `window.__batchBindings` vaut `0`.

## Contournements

**A. Réabonner à la main (Console)**
Le handler est dans une IIFE, il n'est pas accessible. Mais tout ce qu'il fait est reproductible :
```js
document.getElementById('dispatch-batch').addEventListener('click', () => {
  fetch('/api/challenge/05/solve', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      challengeId: '05',
      action: 'validate',
      channel: document.getElementById('channel').value,
      segment: document.getElementById('segment').value
    })
  }).then(r => r.json()).then(console.log);
});
```
puis clique.

**B. Recharger le script au bon moment (Console)**
Le DOM est désormais complet : réinjecter le fichier suffit à ce que le helper trouve sa cible.
```js
const s = document.createElement('script');
s.src = '/c/05-bindings.js';
document.body.appendChild(s);
// puis
document.getElementById('dispatch-batch').click();
```

**C. Rejouer la requête directement**
```js
await fetch('/api/challenge/05/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '05', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

**Event Listeners vide = le problème est en amont du handler.** Ne perds pas de temps à lire
la logique d'envoi. Ensuite, la question devient « quand ce script s'est-il exécuté ? » :
position dans le document, `defer`, `async`, `type="module"`, `DOMContentLoaded`.
Et méfie-toi des helpers `if (!node) return;` : ils transforment une erreur bruyante en panne
muette.
