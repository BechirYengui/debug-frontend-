# Défi 13 : Blocage d'un compte marchand

**Difficulté :** ★☆☆ · **Famille :** le clic arrive, le code déraille.

## Cause

Un simple décalage entre le HTML et le JS. Dans `challenges/13.html`, le champ
« Seuil de blocage (EUR) » porte un id mal orthographié :

```html
<label class="field"><span>Seuil de blocage (EUR)</span>
  <input id="treshold" type="number" min="0" step="50" value="500">
</label>
```

et dans `public/c/13.js`, la fonction `collect()` : appelée en tout premier par le handler
de clic : cherche l'id correctement orthographié (ligne 49) :

```js
function collect() {
  return {
    merchant: el.merchant.value,
    reason: el.reason.value,
    threshold: Number(byId('threshold').value),   // <- byId('threshold') renvoie null
    notify: el.notify.checked,
    note: el.analystNote.value.trim()
  };
}
```

`document.getElementById('threshold')` ne trouve rien et renvoie `null` ; lire `.value`
dessus lève `TypeError: Cannot read properties of null (reading 'value')`. L'exception n'est
pas attrapée : `block()` s'arrête net à sa première ligne, avant la ligne de journal et
avant le `fetch`. Aucune autre partie du code ne lit ce champ (ni à l'initialisation, ni
dans `refresh()`), donc la page se charge sans le moindre avertissement : l'erreur
n'apparaît qu'au clic.

## Diagnostic pas à pas

1. **Console**, puis clic sur *Valider la commande* : une ligne rouge apparaît immédiatement.
   Lis-la **en entier** :
   `Uncaught TypeError: Cannot read properties of null (reading 'value')`.
   Traduction : « j'ai voulu lire `.value` sur quelque chose qui vaut `null` ».
2. À droite du message, le lien `13.js:49`. Clique dessus : DevTools ouvre **Sources** sur
   la ligne fautive, `threshold: Number(byId('threshold').value)`. La flèche de la stack
   trace (déplie le petit triangle si besoin) montre `collect` appelé par `block`, lui-même
   déclenché par le clic.
3. Le seul terme qui peut valoir `null` sur cette ligne est le retour de `byId('threshold')`.
   Vérifie en Console : `document.getElementById('threshold')` → `null`.
4. **Elements** → `Ctrl+F` (ou `Cmd+F`) → tape `#threshold` : *0 of 0*. Le sélecteur ne
   correspond à rien.
5. Regarde le champ « Seuil de blocage » dans la page : clic droit → *Inspecter*.
   L'attribut est `id="treshold"` : il manque le « h ». Le JS et le HTML ne parlent pas du
   même identifiant.
6. **Network** confirme le reste : aucune requête au clic. Le fetch, pourtant correct, n'est
   jamais atteint.

## Contournements

**A. Corriger l'attribut dans Elements**
Sélectionne l'`<input id="treshold">`, double-clique sur la valeur `treshold`, tape
`threshold`, `Entrée`. Reclique sur *Valider la commande* : `collect()` trouve son champ,
le journal affiche « suspension demandée… » puis « réponse 200 ».

**B. Renommer depuis la Console**
```js
document.getElementById('treshold').id = 'threshold';
document.getElementById('block-account').click();
```

**C. Rejouer la requête depuis la Console**
Le handler n'est pas indispensable : la requête attendue se rejoue à la main.
```js
await fetch('/api/challenge/13/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '13', action: 'validate' })
}).then(r => r.json());
```

**D. Rendre le code tolérant, le temps de la session**
Si tu veux garder le vrai flux sans toucher au HTML, tu peux poser un point d'arrêt sur la
ligne 49, et, une fois en pause, exécuter dans la Console
`document.body.insertAdjacentHTML('beforeend', '<input id="threshold" value="500" hidden>')`
puis `F8`. C'est plus long que A ou B, mais cela montre que le scope de la pause est
manipulable.

## Le réflexe à garder

Une erreur rouge dans la Console se lit **jusqu'au bout**, y compris le lien `fichier:ligne`
à droite. `Cannot read properties of null (reading 'x')` a presque toujours le même sens :
**un sélecteur n'a rien trouvé** (`getElementById`, `querySelector`, `closest`…) et on a
enchaîné dessus. Le réflexe est alors mécanique : repérer le sélecteur sur la ligne indiquée,
le rejouer dans la Console, puis le chercher dans Elements avec `Ctrl+F`. Neuf fois sur dix,
c'est une faute de frappe entre le HTML et le JS.
