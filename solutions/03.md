# Défi 03 : Rotation de clé API

**Difficulté :** ★★☆ · **Famille :** le clic n'arrive jamais au bouton.

## Cause

Le bouton est enfermé dans un conteneur :

```html
<div class="rotation-footer" data-state="syncing">
  <div class="actions"><button id="rotate">Valider la commande</button> ... </div>
</div>
```

et `public/c/03.css` :

```css
.rotation-footer[data-state="syncing"]{ pointer-events: none; }
.rotation-footer[data-state="ready"]{ pointer-events: auto; }
```

`pointer-events` est **hérité** : tout le sous-arbre du footer devient transparent au pointeur.
La page fait bien passer l'état à « prêt » à la fin de la synchronisation, mais dans
`finishSync()` elle écrit sur le **mauvais nœud** :

```js
el.syncChip.dataset.state = 'ready';   // le petit badge en haut de la carte
```

Le `<span id="sync-chip">` change d'état, le `<div class="rotation-footer">` reste sur
`syncing` pour toujours. Signature typique d'un refactor où le sélecteur a bougé mais pas
la mise à jour d'état.

Symptôme caractéristique : **le bouton ET la case à cocher voisine sont morts**, alors que
les champs du formulaire au-dessus répondent normalement. Ce n'est donc pas le bouton :
c'est la zone.

## Diagnostic pas à pas

1. Teste la case à cocher « prévenir les propriétaires » : elle non plus ne répond pas.
   Deux éléments indépendants morts dans la même zone → cherche un **ancêtre commun**.
2. **Elements** → sélectionne le bouton → onglet **Computed** → filtre `pointer`.
   `pointer-events: none`. Clique sur la flèche à côté de la valeur : DevTools indique la
   règle et l'élément d'origine.
3. Remonte l'arbre : `div.rotation-footer[data-state="syncing"]`. Sélectionne-le, onglet
   **Styles** : la règle `.rotation-footer[data-state="syncing"]{pointer-events:none}` s'applique.
4. Confirme en Console :
   ```js
   getComputedStyle(document.getElementById('rotate')).pointerEvents  // "none"
   document.querySelector('.rotation-footer').dataset.state           // "syncing"
   document.getElementById('sync-chip').dataset.state                 // "ready"  <-- l'ecart
   ```

## Contournements

**A. Basculer l'état (Elements)**
Édite l'attribut `data-state` du `div.rotation-footer` : `syncing` → `ready`. Le clic passe.

**B. Forcer le style (Styles)**
Sur `.rotation-footer`, ajoute `pointer-events: auto !important;`.

**C. Console**
```js
document.querySelector('.rotation-footer').dataset.state = 'ready';
document.getElementById('rotate').click();
```

**D. Rejouer la requête**
```js
await fetch('/api/challenge/03/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '03', action: 'validate' })
}).then(r => r.json());
```

## Le réflexe à garder

Quand **plusieurs** contrôles voisins sont morts d'un coup, le coupable est un ancêtre.
Le panneau **Computed** est fait pour ça : il donne la valeur effective et remonte à la règle
qui l'impose. `pointer-events`, `visibility`, `opacity`, `cursor` s'héritent ou se propagent :
ne cherche pas la cause sur l'élément lui-même.
