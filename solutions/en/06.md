# Challenge 06: Room booking

**Difficulty:** ★★☆ · **Family:** the click arrives, but the code goes off the rails.

## Cause

The button is inside a `<form>` and has no `type` attribute:

```html
<form id="booking-form" class="booking">
  ...
  <button class="btn btn-primary" id="confirm-booking">Valider la commande</button>
</form>
```

The default `type` of a `<button>` inside a form is **`submit`**. The click therefore
triggers two things: the `confirmBooking` handler, **and** the form submission.
The form has neither `action` nor `method`: the browser navigates to the same URL with a `GET`
and the fields in the query string. That navigation destroys the page's JavaScript context.

And the handler does not survive the race:

```js
function confirmBooking() {
  var f = readForm();
  logLine('réservation demandée : ' + f.slot);
  collectClientContext().then(function (ctx) {   // 120 ms setTimeout
    return fetch('/api/challenge/06/solve', { ... });
  })
  ...
}
```

It waits for a 120 ms asynchronous collection before calling `fetch`. The navigation starts
immediately: the promise is never resolved, **the fetch is not even created**.
No `preventDefault()` anywhere.

## Step-by-step diagnosis

1. Click. The page **flashes** and the URL becomes
   `/challenge/06?date=...&slot=09%3A00-10%3A00&seats=6&costCenter=RD-4120&...`.
   A URL that gains a query string after a click = **form submission**.
   The card's log empties too: the page was reloaded.
2. **Network** → check **Preserve log** before clicking. You then see the
   `challenge/06?...` navigation of type `document` at the top of the list, and **no**
   `challenge/06/solve` request.
3. **Elements**: the button is inside `<form id="booking-form">` and has no `type`.
   ```js
   document.getElementById('confirm-booking').type   // "submit"
   document.getElementById('confirm-booking').form   // <form id="booking-form">
   ```
4. **Sources**: the handler calls `collectClientContext()` (a 120 ms `setTimeout`) before
   `fetch`. Even without that delay the race would be lost; with it, it is lost for sure.
5. To watch it live: Sources → **Event Listener Breakpoints** → *Control* → `submit`.
   The debugger stops on the submission at the moment of the click.

## Workarounds

**A. Change the button type (Elements)**
Add `type="button"` on `<button id="confirm-booking">`. It no longer submits anything, only the
`click` handler runs.

**B. Block the submission (Console)**
```js
document.getElementById('booking-form')
  .addEventListener('submit', e => e.preventDefault());
document.getElementById('confirm-booking').click();
```
(or `document.getElementById('booking-form').onsubmit = () => false;`)

**C. Replay the request**
```js
await fetch('/api/challenge/06/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '06', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

**Preserve log** is the first reflex as soon as a page "flashes": without it, Network
empties on every navigation and you never see what went out (or did not).
Inside a `<form>`, a `<button>` without a `type` is a `submit`. An asynchronous handler (`await`,
`.then`, `setTimeout`) that runs before the send always loses the race against the navigation.
Corollary: `e.preventDefault()` must be **the first line** of the handler, not the last.
