# Challenge 04: Publishing an article

**Difficulty:** ★★☆ · **Family:** the click never reaches the button.

## Cause

The "Contrôle avant mise en ligne" (pre-publication checks) card (`#metrics`, class `.editor-metrics`) carries a
decorative pseudo-element that **overflows downward**:

```css
.editor-metrics{ position: relative; z-index: 3; }
.editor-metrics::after{
  content: "";
  position: absolute;
  left: -14px; right: -14px;
  top: 100%;          /* starts below the card */
  height: 250px;      /* and extends 250 px down */
  background: linear-gradient(180deg, rgba(94,234,212,.07), rgba(94,234,212,0) 78%);
}
```

`top: 100%` places the gradient **after** the card, and its 250 px height makes it cover the whole
action card that follows: including the button. Since `.editor-metrics` is positioned with
`z-index: 3` and `.editor-actions` stays static, the pseudo-element is painted **above**
the button. Hit-testing follows paint order: the `::after` is what catches the click.

The gradient is almost transparent (7% opacity at the top): to the eye, there is nothing to see.

## Step-by-step diagnosis

1. Console empty, Network empty on click → it is not the JS.
2. **Elements** → right-click the button → *Inspect*. DevTools selects
   `div#metrics.card.editor-metrics`, not the button. A neighbor receives the click.
3. Expand `#metrics` in the tree: DevTools shows an `::after` node as a child. Hover it:
   the highlighted area in the page **clearly extends down over the action bar**.
4. Select `::after` → **Styles** tab: `position:absolute; top:100%; height:250px`.
5. Confirm:
   ```js
   const b = document.getElementById('publish').getBoundingClientRect();
   document.elementFromPoint(b.left + b.width/2, b.top + b.height/2);
   // <div id="metrics" class="card editor-metrics">   (the ::after is not a DOM node:
   //  elementFromPoint returns its host element)
   ```
   This mismatch ("I aim at the button, I get back a card located above it") is the
   signature of a pseudo-element or an absolutely positioned child that overflows.

## Workarounds

**A. Make the host transparent to the pointer (Styles)**
On `.editor-metrics`, add `pointer-events: none;`. The pseudo-element inherits it and lets
the click through. (The metrics card has no interactive control, no side effect.)

**B. Neutralize the pseudo-element (Styles)**
Select the `::after` node in Elements and set `content: none;`, `height: 0;` or
`display: none;`.

**C. Move the button out of the covered zone (Elements)**
Drag the `<button id="publish">` node higher in the tree (for instance right before
`#metrics`), or move it up from the Console:
```js
document.body.appendChild(document.getElementById('publish'));
document.getElementById('publish').click();
```

**D. Replay the request**
```js
await fetch('/api/challenge/04/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '04', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

`::before` / `::after` pseudo-elements are painted, therefore **clickable**, and do not appear
in the HTML source: only in the DevTools Elements tree. As soon as a decoration
(gradient, shadow, separator, banner) sits near a dead control, expand the generated nodes
and hover them to see the area they really occupy.
