# Challenge 13: Blocking a merchant account

**Difficulty:** ★☆☆ · **Family:** the click arrives, but the code goes off the rails.

## Cause

A simple mismatch between the HTML and the JS. In `challenges/13.html`, the
"Seuil de blocage (EUR)" (Blocking threshold) field carries a misspelled id:

```html
<label class="field"><span>Seuil de blocage (EUR)</span>
  <input id="treshold" type="number" min="0" step="50" value="500">
</label>
```

and in `public/c/13.js`, the `collect()` function (called first thing by the click
handler) looks for the correctly spelled id (line 49):

```js
function collect() {
  return {
    merchant: el.merchant.value,
    reason: el.reason.value,
    threshold: Number(byId('threshold').value),   // <- byId('threshold') returns null
    notify: el.notify.checked,
    note: el.analystNote.value.trim()
  };
}
```

`document.getElementById('threshold')` finds nothing and returns `null`; reading `.value`
on it throws `TypeError: Cannot read properties of null (reading 'value')`. The exception is
not caught: `block()` stops dead on its first line, before the log line and
before the `fetch`. No other part of the code reads this field (neither at initialization nor
in `refresh()`), so the page loads without the slightest warning: the error
only shows up on click.

## Step-by-step diagnosis

1. **Console**, then click *Valider la commande* (Submit): a red line appears immediately.
   Read it **in full**:
   `Uncaught TypeError: Cannot read properties of null (reading 'value')`.
   Translation: "I tried to read `.value` on something that is `null`".
2. To the right of the message, the link `13.js:49`. Click it: DevTools opens **Sources** on
   the offending line, `threshold: Number(byId('threshold').value)`. The stack trace arrow
   (expand the small triangle if needed) shows `collect` called by `block`, itself
   triggered by the click.
3. The only term that can be `null` on that line is the return value of `byId('threshold')`.
   Check in the Console: `document.getElementById('threshold')` → `null`.
4. **Elements** → `Ctrl+F` (or `Cmd+F`) → type `#threshold`: *0 of 0*. The selector
   matches nothing.
5. Look at the "Seuil de blocage" field in the page: right-click → *Inspect*.
   The attribute is `id="treshold"`: the "h" is missing. The JS and the HTML are not talking
   about the same identifier.
6. **Network** confirms the rest: no request on click. The fetch, correct as it is, is
   never reached.

## Workarounds

**A. Fix the attribute in Elements**
Select the `<input id="treshold">`, double-click the value `treshold`, type
`threshold`, `Enter`. Click *Valider la commande* again: `collect()` finds its field,
the log shows "suspension demandée…" (suspension requested) then "réponse 200" (response 200).

**B. Rename from the Console**
```js
document.getElementById('treshold').id = 'threshold';
document.getElementById('block-account').click();
```

**C. Replay the request from the Console**
The handler is not essential: the expected request can be replayed by hand.
```js
await fetch('/api/challenge/13/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '13', action: 'validate' })
}).then(r => r.json());
```

**D. Make the code tolerant, for the duration of the session**
If you want to keep the real flow without touching the HTML, you can set a breakpoint on
line 49 and, once paused, run in the Console
`document.body.insertAdjacentHTML('beforeend', '<input id="threshold" value="500" hidden>')`
then `F8`. It is longer than A or B, but it shows that the paused scope can be
manipulated.

## The reflex to keep

A red error in the Console is read **all the way to the end**, including the `file:line` link
on the right. `Cannot read properties of null (reading 'x')` almost always means the same thing:
**a selector found nothing** (`getElementById`, `querySelector`, `closest`, and so on) and the
code chained onto it. The reflex is then mechanical: spot the selector on the indicated line,
replay it in the Console, then search for it in Elements with `Ctrl+F`. Nine times out of ten,
it is a typo between the HTML and the JS.
