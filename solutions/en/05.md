# Challenge 05: Sending a batch of notifications

**Difficulty:** ★★☆ · **Family:** the click arrives, but the code goes off the rails.

## Cause

Two scripts, two execution moments:

```html
<head>
  ...
  <script src="/c/05-bindings.js"></script>   <!-- neither defer nor async: runs while the head is being parsed -->
</head>
<body>
  ... the #dispatch-batch button is here ...
  <script src="/c/05.js" defer></script>
</body>
```

`05-bindings.js` contains the complete handler (`onDispatch`, with a perfectly
correct `fetch`) and subscribes it through a home-made helper:

```js
function on(selector, type, handler, opts) {
  var node = d.querySelector(selector);
  if (!node) return false;          // <-- silent failure
  node.addEventListener(type, handler, opts || false);
  bound += 1;
  return true;
}
on('#dispatch-batch', 'click', onDispatch);
```

When this script runs, the `<body>` has not been parsed yet:
`document.querySelector('#dispatch-batch')` returns `null`, the helper exits via `return false`
and **nothing gets subscribed**. No exception, no log: the helper swallows the failure.
The subscriptions from the same file on `window` and `document` (`beforeunload`, `visibilitychange`)
do work, since those objects already exist: so the page looks "alive".

`05.js` (loaded with `defer`, hence after the DOM is parsed) handles the table, the filters and
the preview: everything that works comes from there.

## Step-by-step diagnosis

1. Console empty, Network empty on click. The button is neither covered nor `disabled`:
   `Inspect` does return `button#dispatch-batch`.
2. **Elements** → button selected → **Event Listeners** panel, uncheck *Ancestors*.
   The list is **empty**. There is no handler: no point looking for why the fetch
   fails, it is never reached.
   In the Console (Chrome): `getEventListeners(document.getElementById('dispatch-batch'))` → `{}`.
3. **Sources**: open `05-bindings.js`. You find `onDispatch` with the right `fetch`, and
   `on('#dispatch-batch', 'click', onDispatch)`.
4. Set a breakpoint on the line `var node = d.querySelector(selector);` and reload.
   The pause happens **before** the button exists: `node` is `null`, `document.body`
   is `null`, `document.readyState` is `"loading"`.
5. Look at where the file is loaded: `<head>`, with neither `defer` nor `async`. Compare with `05.js`,
   loaded at the end of `<body>` with `defer`: that one finds everything.
6. The page even exposes the counter: in the Console, `window.__batchBindings` is `0`.

## Workarounds

**A. Re-subscribe by hand (Console)**
The handler lives in an IIFE, it is not reachable. But everything it does can be reproduced:
```js
document.getElementById('dispatch-batch').addEventListener('click', () => {
  fetch('/api/challenge/05/solve', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      challengeId: '05',
      action: 'validate',
      channel: document.getElementById('channel').value,
      segment: document.getElementById('segment').value
    })
  }).then(r => r.json()).then(console.log);
});
```
then click.

**B. Reload the script at the right time (Console)**
The DOM is now complete: re-injecting the file is enough for the helper to find its target.
```js
const s = document.createElement('script');
s.src = '/c/05-bindings.js';
document.body.appendChild(s);
// then
document.getElementById('dispatch-batch').click();
```

**C. Replay the request directly**
```js
await fetch('/api/challenge/05/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '05', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

**Empty Event Listeners = the problem is upstream of the handler.** Do not waste time reading
the sending logic. The question then becomes "when did this script run?":
position in the document, `defer`, `async`, `type="module"`, `DOMContentLoaded`.
And beware of `if (!node) return;` helpers: they turn a loud error into a
silent failure.
