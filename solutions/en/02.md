# Challenge 02: Valve opening

**Difficulty:** ★☆☆ · **Family:** the click never reaches the button.

## Cause

The button carries the `disabled` attribute directly in the HTML:

```html
<button class="btn btn-primary" id="open-valve" disabled aria-disabled="true">Valider la commande</button>
```

The page's code does compute the "ready" state (all 5 interlocks pass) but, in
`applyReadiness()`, all it does is:

```js
el.open.setAttribute('aria-disabled', ready ? 'false' : 'true');
el.open.classList.toggle('is-ready', ready);
```

It updates the ARIA attribute and a CSS class, **never the `disabled` property**.
And `public/c/02.css` contains:

```css
.btn.is-ready{ opacity: 1; cursor: pointer; box-shadow: ...; }
```

which overrides the `.btn[disabled]{opacity:.45;cursor:not-allowed}` style from the shared stylesheet.
Result: the button **looks active** (opaque, pointer cursor, glow) while it is inert.
A `disabled` element receives no mouse event at all: no `click`, no `mousedown`.

## Step-by-step diagnosis

1. **Console**: empty. **Network**: nothing on click.
2. **Elements**: select the `<button>` and read the opening tag **in full**.
   `disabled` is there, after the classes. That is the trap: you read `class="btn btn-primary is-ready"`
   and skip the next attribute.
3. Check in the Console:
   ```js
   const b = document.getElementById('open-valve');
   b.disabled            // true
   b.matches(':disabled') // true
   ```
4. Elements → **Event Listeners**: the `click` listener is there. The handler exists,
   it is never triggered.
5. The gap between `aria-disabled="false"` and a present `disabled` is the signature of the bug:
   someone updated accessibility and styling, not the real state.

## Workarounds

**A. Remove the attribute (Elements)**
Double-click `disabled` in the tag → clear it → `Enter`. Then click.
(Or right-click the node → *Edit attribute*.)

**B. Console**
```js
document.getElementById('open-valve').disabled = false;
document.getElementById('open-valve').click();
```

**C. Replay the request**
```js
await fetch('/api/challenge/02/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '02', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

`disabled` is a **DOM state**, not a style. A page can perfectly well display an "active"
button and leave it inert. On a dead button, always look at the raw attributes
(`disabled`, `readonly`, `inert`, `aria-disabled`) before the CSS, and compare `:disabled` with
the appearance.
