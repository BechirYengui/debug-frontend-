# Challenge 01: Release promotion

**Difficulty:** ★☆☆ · **Family:** the click never reaches the button.

## Cause

`challenges/01.html` mounts a `<div id="view-transition">` right before the card.
`public/c/01.css` gives it:

```css
.view-transition{ position: fixed; inset: 0; z-index: 9000; background:#0b0e14; opacity: 1; }
.view-transition.is-idle{ opacity: 0; }
```

The script adds `is-idle` on the first `requestAnimationFrame`: the overlay becomes **invisible**
(`opacity: 0`) but stays in the flow, in `position: fixed`, covering the whole window and sitting
above the card. `opacity: 0` has no effect on hit-testing: the overlay keeps receiving
every click. The button's handler (`el.promote.addEventListener('click', send)`) is
correctly attached, it is simply never called.

This is the classic production bug: a transition screen whose opacity gets animated instead
of being torn down (`display:none`, `remove()`, `pointer-events:none`).

## Step-by-step diagnosis

1. **Console**: nothing. No error. First signal: the problem is not in the JS.
2. **Network**: no request on click. The fetch is never reached.
3. **Elements** → right-click the button in the page → *Inspect*.
   DevTools selects `div#view-transition`, **not** the `<button>`. That is the answer.
   (DevTools inspects the element actually under the cursor, the one that would receive the click.)
4. Confirm in the Console:
   ```js
   document.elementFromPoint(
     ...(r => [r.left + r.width/2, r.top + r.height/2])(document.querySelector('#promote').getBoundingClientRect())
   )
   // <div id="view-transition" class="view-transition is-idle">
   ```
5. Select `#view-transition` in Elements: the highlighted rectangle covers the whole window.
   **Styles** tab → `position: fixed; inset: 0; z-index: 9000`.

## Workarounds

**A. Delete the node (Elements)**
Select `div#view-transition` → press `Delete`. The click goes through, the request goes out.

**B. Neutralize it in CSS (Styles)**
On `.view-transition`, add `pointer-events: none;` (or `display: none`).
The live-edited rule is enough, no need to touch the file.

**C. From the Console**
```js
document.getElementById('view-transition').remove();
document.getElementById('promote').click();
```

**D. Replay the request without touching the DOM**
```js
await fetch('/api/challenge/01/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '01', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

A button that does not react and an empty Console: **before reading the JS, check who
really receives the click**. `Inspect` on the element, or `document.elementFromPoint(x, y)`.
`opacity: 0` and `visibility: hidden` do not disable events; `display: none` and
`pointer-events: none` do.
