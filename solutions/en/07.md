# Challenge 07: Shipping an order

**Difficulty:** ★★★ · **Family:** the click arrives, but the code goes off the rails.
The code lives in `public/c/07.js`, minified on a single line.

## Cause

The button has **no** listener of its own. All the card's interactivity goes through a
delegation attached to `document`:

```js
document.addEventListener("click", function (e) {
  var t = e.target.closest ? e.target.closest("[data-cmd]") : null;
  if (!t) { cls(); return; }
  var c = t.getAttribute("data-cmd");
  if (c === "dispatch") { tx(); return; }   // <- the send
  if (c === "pick")     { S.ref = t.getAttribute("data-ref"); upd(); return; }
  if (c === "tip")      { pop(t); return; }
});
```

But the card itself, `#order-panel`, which is an **ancestor** of the button, cuts the bubbling:

```js
E.panel.addEventListener("click", function (e) {
  e.stopPropagation();                                   // <- here
  if (!e.target.closest("[data-cmd=tip]")) { cls(); }
});
```

This listener exists for a plausible reason: closing popovers when you click elsewhere,
without the "inner" click triggering the global close. But `stopPropagation()`
stops propagation **for every listener located higher up**, including the delegation on
`document`. The `click` event is born on the button, bubbles up to `#order-panel`, and dies there.

Revealing symptom: **nothing** that is delegated works inside the card:
neither the button, nor the row selection (`data-cmd="pick"`), nor the tooltip (`data-cmd="tip"`).
The `<select>` elements and the `<input>`, on the other hand, subscribed directly, respond perfectly.

## Step-by-step diagnosis

1. **Console** empty, **Network** empty. The button is indeed the click target
   (`Inspect` → `button#dispatch-order`), it is not `disabled`, `pointer-events` is `auto`.
2. **Elements** → button selected → **Event Listeners**:
   - uncheck *Ancestors*: the list is empty, no listener of its own.
   - check *Ancestors* again: two `click` entries appear, one on `div#order-panel`, the other on
     `document`. The useful handler is at the very top, and there is something in between.
3. In the Console (Chrome):
   ```js
   getEventListeners(document).click.length            // 1
   getEventListeners(document.getElementById('order-panel')).click  // 1 listener
   ```
4. Confirm the cut without reading the code:
   ```js
   document.addEventListener('click', e => console.log('atteint document ?'), true);  // capture: goes through
   document.addEventListener('click', e => console.log('remonte jusqu au document'));  // bubble: silent
   ```
   The capture phase arrives, the bubble phase does not → someone calls `stopPropagation`
   between the two.
5. **Sources** → open `07.js` → **`{}`** button (Pretty print) at the bottom of the panel.
   Search for `stopPropagation`. You land on the `#order-panel` listener.
   Variant without reading: Sources → **Event Listener Breakpoints** → *Mouse* → `click`,
   then click and step with `F9`: you see the panel's handler run, and never the
   document's.

## Workarounds

**A. Neutralize `stopPropagation` (Console)**
The fastest, and without touching the DOM:
```js
Event.prototype.stopPropagation = function () {};
document.getElementById('dispatch-order').click();
```

**B. Remove the offending listener (Console, Chrome)**
`getEventListeners` gives the exact reference of the anonymous function:
```js
const panel = document.getElementById('order-panel');
const l = getEventListeners(panel).click[0];
panel.removeEventListener('click', l.listener, l.useCapture);
document.getElementById('dispatch-order').click();
```

**C. Move the button out of the subtree (Elements)**
The delegation is on `document`: outside `#order-panel`, the click bubbles up unobstructed.
```js
document.body.appendChild(document.getElementById('dispatch-order'));
document.getElementById('dispatch-order').click();
```
(In Elements, simply dragging and dropping the node out of the card does the same thing.)

**D. Replay the request**
```js
await fetch('/api/challenge/07/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '07', action: 'validate' })
}).then(r => r.json());
```
Careful: `dispatchEvent(new MouseEvent('click', {bubbles:true}))` on the button **does not work**:
the synthetic event bubbles along the same path and gets cut at the same place.

## The reflex to keep

Check **Ancestors** in Event Listeners: that is where delegation hides. When the
useful handler is on `document` or `body`, any intermediate ancestor can kill it with
`stopPropagation()`: often added to handle a popover or a menu.
The capture-vs-bubble test (`addEventListener(..., true)`) pinpoints the cut in two lines,
without reading a single line of the bundle.
