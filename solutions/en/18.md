# Challenge 18: Re-arming an alarm

**Difficulty:** ★★★ · **Family:** the click arrives, but the code goes off the rails.
The code lives in `public/c/18.js`, minified on a single line.

## Cause

The button's listener is attached with the `once` option:

```js
function h(e) {
  if (!e.isTrusted) { log("auto-test du bouton OK"); return; }
  tx();
}
E.go.addEventListener("click", h, { once: true, passive: true });   // <- once
```

and initialization ends with a "self-test" that **dispatches a synthetic click** on
that very button:

```js
function selftest() {
  E.go.dispatchEvent(new MouseEvent("click", { bubbles: true, cancelable: true }));
}
...
opts(); upd(); selftest(); log("alarme TEMP-HIGH chargée, 3 capteurs");
```

An event created by `dispatchEvent` has `isTrusted === false`: `h()` logs
"auto-test du bouton OK" (button self-test OK) and stops without calling `tx()`. But as far as
the browser is concerned, **the listener has been invoked**, and `once: true` **removes it
immediately**. When the human clicks, the button no longer has any `click` listener. Nothing
happens: no log, no request, no error. `tx()`, which contains a perfectly correct `fetch`, is
never called.

## Step-by-step diagnosis

1. **Network** on click: nothing. **Console**: nothing. The button does not react at all: not
   even a line in the page's log. Look at that log: on load, it contains
   "auto-test du bouton OK". So something has already "clicked" for you.
2. **Elements** → select the `#rearm-alarm` button → **Event Listeners** tab
   (untick *Ancestors* to keep only the element): **no `click`**. In the Console,
   `getEventListeners($0)` returns `{}`. Yet the code does attach a listener: it has been removed.
3. **Sources** → `18.js` → **`{}`** Pretty print → `Ctrl+F` `addEventListener("click"`.
   You find `E.go.addEventListener("click", h, {once: true, passive: true})`, then right
   below it `selftest()`, whose body does a `dispatchEvent(new MouseEvent("click", …))`.
4. Proof through the debugger: set a breakpoint on the `selftest();` line and **reload**.
   At the pause, go back to Elements → the button's Event Listeners: the `click` listener is
   there, with **`once` ticked**. Resume (`F8`): it disappears. The culprit is the statement
   you just stepped over.
5. Another angle: Sources → **Event Listener Breakpoints** → *Mouse* → tick **click**, then
   reload. The debugger stops in `h()` **during page load**, before any human
   click; in the Scope panel, `e.isTrusted` is `false`. A synthetic `click` counts
   as an invocation for `once`.

## Workarounds

**A. Neutralize the self-test before it consumes the listener**
Breakpoint on the `selftest();` line (pretty-printed file), reload. At the pause, in
the Console (closure context):
```js
E.go.dispatchEvent = function () {}
```
Then `F8`. `selftest()` now calls an empty function, the `once` listener survives, and your
real click calls `tx()` → **200**.

**B. Re-attach the listener from any pause inside the closure**
Being paused in the script's scope is enough to reach `E` and `tx`. For example:
breakpoint in `upd()` (first line), then change the value of the "Intervention" select
to trigger it. At the pause, in the Console:
```js
E.go.addEventListener('click', tx)
```
`F8`, then click "Valider la commande" (Submit): `tx()` fires, without `once` this time.
(Variant: `E.go.addEventListener('click', h)` puts back the original listener, which tests
`isTrusted`: a real click goes through.)

**C. Replay the request from the Console**
```js
await fetch('/api/challenge/18/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '18', action: 'validate' })
}).then(r => r.json());
```

**D. Verify your diagnosis with `getEventListeners`**
This is not a workaround, but it is the tool that settles it in one line: select the
button in Elements, then in the Console `getEventListeners($0)` → `{}` before the repair;
after A or B → `{click: [{listener: ƒ, once: false, passive: false, …}]}`. On the pause of
workaround A, before `F8`, you would see `once: true`.

## The reflex to keep

**Empty Event Listeners while the code attaches a listener = it has been removed.** The two
usual suspects: the **`once`** option (removed after the first invocation) and the
**`signal`** option (removed when an `AbortController` is aborted). And remember that
**`dispatchEvent` counts as an invocation**: a self-test, an initialization `.click()`
or a framework that "simulates" an event is enough to consume a `once`. The
`isTrusted` field distinguishes the human click from the synthetic one, but it does not protect
the listener.
