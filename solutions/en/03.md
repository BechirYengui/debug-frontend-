# Challenge 03: API key rotation

**Difficulty:** ★★☆ · **Family:** the click never reaches the button.

## Cause

The button is locked inside a container:

```html
<div class="rotation-footer" data-state="syncing">
  <div class="actions"><button id="rotate">Valider la commande</button> ... </div>
</div>
```

and `public/c/03.css`:

```css
.rotation-footer[data-state="syncing"]{ pointer-events: none; }
.rotation-footer[data-state="ready"]{ pointer-events: auto; }
```

`pointer-events` is **inherited**: the footer's whole subtree becomes transparent to the pointer.
The page does switch the state to "ready" at the end of the sync, but in
`finishSync()` it writes to the **wrong node**:

```js
el.syncChip.dataset.state = 'ready';   // the small badge at the top of the card
```

The `<span id="sync-chip">` changes state, the `<div class="rotation-footer">` stays on
`syncing` forever. Typical signature of a refactor where the selector moved but the
state update did not.

Telltale symptom: **the button AND the neighboring checkbox are both dead**, while
the form fields above respond normally. So it is not the button:
it is the zone.

## Step-by-step diagnosis

1. Try the "prévenir les propriétaires" (notify owners) checkbox: it does not respond either.
   Two independent elements dead in the same zone → look for a **common ancestor**.
2. **Elements** → select the button → **Computed** tab → filter `pointer`.
   `pointer-events: none`. Click the arrow next to the value: DevTools points to the
   rule and the element it comes from.
3. Walk up the tree: `div.rotation-footer[data-state="syncing"]`. Select it,
   **Styles** tab: the rule `.rotation-footer[data-state="syncing"]{pointer-events:none}` applies.
4. Confirm in the Console:
   ```js
   getComputedStyle(document.getElementById('rotate')).pointerEvents  // "none"
   document.querySelector('.rotation-footer').dataset.state           // "syncing"
   document.getElementById('sync-chip').dataset.state                 // "ready"  <-- the gap
   ```

## Workarounds

**A. Flip the state (Elements)**
Edit the `data-state` attribute of `div.rotation-footer`: `syncing` → `ready`. The click goes through.

**B. Force the style (Styles)**
On `.rotation-footer`, add `pointer-events: auto !important;`.

**C. Console**
```js
document.querySelector('.rotation-footer').dataset.state = 'ready';
document.getElementById('rotate').click();
```

**D. Replay the request**
```js
await fetch('/api/challenge/03/solve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ challengeId: '03', action: 'validate' })
}).then(r => r.json());
```

## The reflex to keep

When **several** neighboring controls die at once, the culprit is an ancestor.
The **Computed** panel is made for this: it gives the effective value and traces it back to the rule
that imposes it. `pointer-events`, `visibility`, `opacity`, `cursor` are inherited or propagate:
do not look for the cause on the element itself.
